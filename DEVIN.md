# Standing instructions for Devin

Read this before touching anything. Per-iteration instructions arrive in the
session prompt; this file is the part that does not change.

## What this repository is

A patient-specific orthopaedic bone plate, generated by code. You are the
engineer. `autoimplants/generator.py` builds the part, the validators in
`autoimplants/validators/` grade it, and your job is to change the design until
it passes.

Coordinate frame, matching `inputs/bone.stl`:

- **+Z** along the femoral shaft, proximal to distal
- **+X** lateral — the aspect the plate mounts on, and the plate thickness direction
- **+Y** the plate width direction

## Setup

```bash
bash setup.sh
```

Python 3.12 is mandatory, not a preference: CadQuery/OCP publish no wheels for
3.13 or 3.14, and a newer interpreter fails at install time with an unhelpful
resolver error. If `uv` is missing, use `python3.12 -m venv .venv`.

## Checking your work

```bash
.venv/bin/python -m autoimplants.run --validators geometry,stress
```

Exit 0 = passes, exit 1 = fails. The failure table gives you a measured value, the
limit it broke, and the location in the part. Read the locations; they exist so
you do not have to guess where the problem is.

Run it after every change. Never commit a design you have not validated.

## What you may change

| | |
|---|---|
| `autoimplants/generator.py` | **Editable — this is the point.** |
| `autoimplants/params.py` | Editable. |
| `autoimplants/export.py` | Editable. |
| `runs/` | Editable — write your artefacts here. |
| `out/` | Editable — build and report output lands here. |
| everything else | **Locked.** |

Specifically locked, and why:

- `inputs/**` — anatomy, surgical plan, load cases, pass thresholds. Screw
  positions and keepout zones are pre-solved surgical planning input. The implant
  accommodates them; they do not move.
- `autoimplants/validators/**` — a design does not get to rewrite its own examiner.
- `autoimplants/bone.py` — the validator measures the bone gap through this
  module. Editing it changes the measurement instead of the design.
- `autoimplants/contracts.py`, `harness/**`.

This is enforced mechanically by `harness/guard.py` after every session. A commit
that touches a locked file makes the iteration invalid. **Relaxing a threshold is
not a fix.** If you believe a constraint is genuinely infeasible, say so in the
structured output and stop — do not edit your way around it.

## Parameters alone will not get you there

`params.py` declares four topology handles — `thickness_profile`, `ribs`,
`hole_slots`, `contour_spline` — and `build_implant()` **raises
NotImplementedError** if you set one without implementing the geometry. This is
intentional. To use a handle you must write the code in `generator.py` and flip
the matching `*_IMPLEMENTED` flag. `_guard_unimplemented()` documents how each one
is meant to work.

Check the arithmetic before reaching for a scalar tweak:

- Uniform thickening is capped by the 39 g implant mass budget. The baseline is
  already 37.0 g, so you have about 5% more volume — worth roughly a 1.11×
  bending-stress reduction.
- Widening past 17.6 mm hits the `perforating_vessel_bundle` keepout at mid-span (zone centre y=14.8 mm less its 6.0 mm radius); the baseline sits at 16 mm.
- Lengthening in either direction hits the proximal and distal keepouts.

When the numbers say a scalar change cannot close the gap, change the geometry.
Local reinforcement is cheap in mass and expensive in code, and that trade is the
whole reason this project exists.

## Commit messages are a deliverable

Each commit becomes part of the design history file for this part — a
legally-required medical-device artefact that here falls out of the process for
free. Write for the engineer who inherits the design:

```
<short summary of the geometric change>

Failure addressed: <check id> measured <value> <unit> against a <limit> limit.
Change: <what you changed geometrically, and why it addresses the mechanism>
Rejected: <what you considered and why it could not work>
Result: <check values after the change>
```

State the mechanism, not just the edit. One commit per design change.
